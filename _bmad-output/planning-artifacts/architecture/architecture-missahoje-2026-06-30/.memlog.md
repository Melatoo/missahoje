- (decision) Purpose: build-substrate. Mode: Coaching path. User wants to learn architecture concepts.
- (decision) AD-1: Strict Modular Layered Architecture for API. Binds: All backend modules. Prevents: Tight coupling and spaghetti code. Rule: Strict separation of concerns (Module -> Controller -> Service -> Repository). Controllers handle HTTP, Services handle business logic, Repositories handle data access. Downward dependency only.
- (decision) AD-2: Strict API Contract via DTOs. Binds: API responses to Web Frontend. Prevents: Database schema leakage to the frontend. Rule: Database Entities MUST NEVER cross the API boundary. The Controller must map Entities to DTOs before responding.
- (decision) AD-3: Server-Driven State for Next.js. Binds: missahoje-web data fetching. Prevents: Client-side state bloat and redundant API calls. Rule: Primary data fetching happens in Server Components. Interactions that change context (e.g. city change) mutate server state (cookies/URL) and trigger router.refresh() for a soft-refresh.
- (event) spine finalized
